DiffCycle Documentation

DiffCycle 文档

DiffCycle 把「页面和设计稿差多少」从一个形容词变成一个可以复算的数字：严格差异占比、门槛口径、感知口径，以及一份可以直接放进对话的三联图。本文档覆盖安装、参数、判定规则、写闸门与 CI。

文档已上线 版本 0.3 更新于 2026-10-31 Node.js ≥ 22

快速开始#

三步：从装上到拿到第一个数字。

  1. 装上 MCP 服务

    在你的项目里跑安装器，选你正在用的那个宿主。下面以 Codex 为例，其它宿主的命令见安装。

    bash
    node scripts/install-codex.mjs --target .
  2. 确认它装对了

    安装器支持只读模式，先看清楚它要动哪些文件再让它真正动手。

    bash
    node scripts/install-codex.mjs --target . --check   # 只报告，不改任何文件
node scripts/install-codex.mjs --target . --dry-run # 预览将要写入的内容
  3. 让你的 Agent 量一次

    把这句话原样粘给你的编码 Agent：

    text
    用 diffcycle_measure 量一下这个页面和设计稿的差异，把 diff 和 withinGate 给我。

    它会返回一个文本块（全部数字）和一张图片块（设计稿 | 实测渲染 | 差异热区）。数字才是结论，图片只是让你一眼看到差在哪。

装的时候必须两件都装

只装 MCP 服务，Agent 不知道什么时候该用它；只装 Skill 或规则文件，Agent 会自己编一个数字出来。MCP 工具负责「量」，Skill / 规则文件负责「什么时候量」，两者缺一不可。

装完之后

即使你没跟 Agent 说过任何提示语，只要它听到「哪里不一样」「跟设计稿对一下」这类话，也会主动调用 DiffCycle——触发词是按用户真会说的话写的，不是按技术术语写的。

它是怎么工作的#

DiffCycle 有四层接入，各管一段事，不要混着用：

CLI

干活。你自己跑，或者 CI 跑，产出数字和产物文件。

MCP

模型决定要不要调用。工具摆在模型面前，用不用是模型的事。

Hook

什么时候自动触发。改文件之前强制测量，不达标直接阻断。

CI

兜底。PR 上跑一遍，不达标就让流水线红。

闭环形态 模型负责提议改法，DiffCycle 负责裁决。
模型永远不能自己宣布完成——只有 withinGate 能宣布达标。

一次测量里发生了什么

  1. 取设计稿

    本地 PNG 路径，或一个 Figma 节点链接（需要 FIGMA_TOKEN）。

  2. 渲染候选页面

    把 candidateUrl 指向的页面渲染成位图。

  3. 逐像素比对

    在 OKLab 色彩空间里算每像素距离，再按三套容差分别统计：严格、门槛、感知。

  4. 聚成差异区域

    把相邻的差异像素合并成有意义的矩形块，按 added / removed / modified 分类。

  5. 裁决

    按验收线算出 withinGate，写出产物文件，把数字和三联图一起交回去。

没有任何抽样

每个数字都来自完整的逐像素计算，不是估算、不是抽样、不是模型看图看出来的。

安装#

先决条件

项要求说明
Node.js≥ 22安装器用 Node 绝对路径调用，避免宿主 PATH 里没有 node。
FIGMA_TOKEN可选只有要直接拉 Figma 节点时才需要；从本地 PNG 比对完全不需要。
宿主其一Codex / Claude Code / Cursor / Cascade / Kiro，或任何支持 MCP 的宿主。

一条命令

每个宿主一个安装器，命令形状完全一样：

bash
node scripts/install-claude-code.mjs --target .
node scripts/install-codex.mjs       --target .
node scripts/install-cursor.mjs       --target .
node scripts/install-cascade.mjs      --target .
node scripts/install-kiro.mjs         --target .

安装器的共同行为

  • 幂等：已经是目标状态时什么都不做，不会产生多余改动。
  • 改前备份：要动既有配置时，先备份到 .diffcycle/backup/。
  • 不破坏邻居：只增改自己那一段，别人的配置原样保留。
  • 不写凭据值：只声明环境变量名，取值由宿主环境继承。
  • 可先看再动：--dry-run 预览，--check 只报告当前状态。
凭据值永远不进代码库

安装器写进配置的是变量名（例如 FIGMA_TOKEN），不是值。值请由宿主的环境变量提供。

核心概念#

DiffCycle 一次给出三个差异占比，因为「差多少」取决于你允许多大的偏差。三个数各有用途，缺一个都会误判。

口径判定回答的问题
strict任何像素差异都算差异，不给容差「有没有一丁点不一样」
gate每像素 OKLab 距离 ≤ 0.05 才算相同「有没有超出验收线的偏差」
perceptual每像素 OKLab 距离 ≤ 0.2 才算相同「人眼能不能看出来」

阈值常量

常量值作用
DEFAULT_LOCATING0.01定位容差，用于判断「同一处内容」。
DEFAULT_GATE0.05门槛口径容差。
DEFAULT_PERCEPTUAL0.2感知口径容差。
SSIM_WORST_MIN0.95最差分块 SSIM 下限。
SSIM_MEAN_MIN0.985平均 SSIM 下限。
REGION_MIN_PIXELS14区域聚合的最小像素数。
REGION_MIN_PIXELS_LARGE_DIFF6大差异区域的最小像素数。
REGION_CONTENT_STD8区域内容标准差阈值。
TILE_SIZE / WINDOW_SIZE64 / 16分块与滑窗尺寸。
SSIM_BLOCK64SSIM 计算块尺寸。
关于 SSIM

这里的 SSIM 是自定义实现，不是标准化 SSIM，数值不能直接和论文或第三方工具横向比较。它在本工具内部的作用是给区域聚合提供第二个信号。

验收线怎么判

验收线判定式 withinGate = (strictDiffPercentage ≤ gateThreshold × 100)
默认 gateThreshold = 5，即严格差异占比不高于 5% 才算达标。

判定用的是严格口径：哪怕只差一点，只要严格占比超过 5% 就不达标。这是刻意的保守选择——门槛口径用来描述「偏差有多大」，验收线用来决定「能不能交付」，两件事分开。

差异区域

每个差异区域带一个矩形框、分类和像素占比：

  • added：候选页面上多出来的内容（设计稿里没有）。
  • removed：候选页面上缺失的内容（设计稿里有）。
  • modified：两边都有，但像素不一致。

区域的 share 表示它占差异像素的百分比，不是占整页的百分比。

产物

一次测量会在 outputDir（默认 .diffcycle/measurements）留下五件套：

文件内容
design.png设计稿原图
candidate.png候选页面的实测渲染
diff.png差异热区图（合法 PNG）
comparison.png三联图：设计稿 | 实测渲染 | 差异热区
summary.json全部数字与区域清单
三联图是定位器，不是测量器

缩放采用最近邻，不会插值造出原图里没有的颜色。图中颜色只用来告诉你「哪儿」，所有数字都来自像素内核。

在编码 Agent 里使用#

diffcycle_measure

最常用的工具。一次测量，给你全部数字 + 一张三联图。

参数必填说明
candidateUrl必填待测页面的地址，本地 http://127.0.0.1:xxxx 即可。
designPngPath二选一设计稿 PNG 的本地路径。
designFigmaUrl二选一Figma 节点链接，需要 FIGMA_TOKEN。
outputDir可选产物目录，默认 .diffcycle/measurements。
includeImage可选是否把三联图放进对话，默认开。
json
{
  "candidateUrl": "http://127.0.0.1:8899/index.html",
  "designPngPath": "D:/design/checkout.png"
}
json
{
  "candidateUrl": "http://127.0.0.1:8899/index.html",
  "designFigmaUrl": "https://www.figma.com/design/xxxxx?node-id=1-2"
}
参数形状说明

设计稿来源用扁平参数给：designPngPath 与 designFigmaUrl 二选一，不需要嵌套结构，也不需要记判别器。outputDir 可以省略。

返回值

  • 文本块：三个口径的差异占比、区域数与分类、变化像素数、withinGate、最大差异区域的坐标与占比。
  • 图片块（image/png）：设计稿 | 实测渲染 | 差异热区，总宽 916×802。

怎么跟 Agent 说话

触发词是按人真会说的话写的。下面这些说法都应该能触发：

中文
  • 「这个页面和设计稿差多少？」
  • 「跟设计稿对一下」
  • 「哪里不一样？」
  • 「改完看着还是不太对」
  • 「帮我看看有没有走样」
English
  • “how far off is this from the design?”
  • “compare this with the Figma frame”

首次激活

关于 MCP Apps

MCP Apps 是 MCP 的官方扩展机制，允许工具声明一个交互式 UI。DiffCycle 当前返回的是标准 image content block（三联图），还没有接上 MCP Apps 的交互式 UI 这一层。图已经能直接看，交互面板是下一步。

写闸门（Hook）#

写闸门是 DiffCycle 的强制层：改文件之前先测量，未达门槛直接阻断，并把理由回灌给 Agent。这样 Agent 就没法随口说一句「已经好了」。

它怎么工作

  1. 拦在写之前

    宿主在执行写工具之前触发闸门，闸门拿到工具名、目标路径和当前工作区。

  2. 找最近一次测量

    在工作区里找最近一次成功的测量记录；找不到就拒绝。

  3. 比新旧

    目标文件比那次测量新 → 说明改完没重新量 → 拒绝。

  4. 裁决并回灌

    不达标时退出码 2，理由写进 stderr，宿主把它交回给 Agent。

阻断契约 退出码 2 + stderr 说明理由 = 阻断。
退出码 0 = 放行。

一份判定，多个薄适配器

判定逻辑集中在宿主无关的一份核心里，各宿主适配器只负责说清两件事：哪些工具算写、路径在哪个字段。这样几家宿主的判定结果不会互相漂移。

宿主算「写」的工具路径来源
Kirofs_write / fs_append / str_replace / delete_file / edit_file / notebook_edit工具入参里的路径字段（含 notebook_path）。
Claude CodeWrite / Edit / MultiEdit / NotebookEdit工具入参里的文件路径。
Codexapply_patch工具入参里没有路径，只有 patch 文本——适配器会解析出 patch 里的每一个文件路径，任一文件比测量新就整包拒绝。
Cursor由宿主语义决定闸门是否生效，以 Cursor 的实际行为为准。
Codex：多个 Hook 是并发启动的

官方明确同一事件的多个 Hook 并发执行，一个拦不住另一个。所以每个闸门都必须自己 fail-closed，不能指望自己是唯一一个。

fail-closed 是什么意思

找不到测量记录、解析不了输入、脚本崩溃——一律按「拒绝写入」处理，而不是「放行」。一个坏掉的闸门看起来是健康的，实际什么也拦不住，所以宁可误拦。

闸门的环境变量

变量默认作用
DIFFCYCLE_GATE_DISABLED未设置设为 1 关闭闸门。
DIFFCYCLE_GATE_STATE.diffcycle/gate-state.json闸门状态文件位置。
DIFFCYCLE_GATE_MEASURE_DIR.diffcycle/measurements测量记录目录。
DIFFCYCLE_GATE_EXTRA_WRITE_TOOLS空宿主追加的写工具名。
DIFFCYCLE_GATE_ROOT宿主传入闸门的工作区根。

闸门日志写在工作区的 .diffcycle/gate.log，每次拦截都会记一笔。

不想被拦？

只装 MCP 服务、不装写闸门，Agent 照样会去量，只是没人拦它说「好了」。这是有意留的退路：临时赶进度时用 DIFFCYCLE_GATE_DISABLED=1 关掉，跑完记得关回来。

CI 集成#

CI 是最后一道兜底：不管 Agent 说了什么，流水线只看 withinGate。

  1. 把候选页面跑起来

    构建产物用一个本地静态服务托管，拿到一个 candidateUrl。

  2. 跑一次测量

    用 CLI 或 MCP 工具跑 diffcycle_measure，设计稿从 PNG 或 Figma 取。

  3. 按 withinGate 决定成败

    withinGate = false 就让这一步失败。

  4. 把证据传上去

    把 comparison.png、diff.png 和 summary.json 作为 artifact 传到流水线界面，评审时能直接看图。

CI 判定式 exit code = withinGate ? 0 : 1
为什么 CI 不可省

写闸门只覆盖「本机上的 Agent 改文件」这条路径。直接 push 的改动、别人提的 PR、脚本批量改动，都只有 CI 能拦住。

故障排查#

Agent 根本不调用 DiffCycle 工具 触发

几乎都是「只装了一半」。

  1. 确认 MCP 服务注册成功：让 Agent 列出可用工具，看有没有 diffcycle_measure。
  2. 确认规则 / Skill 文件在位（Claude Code 的 .claude/skills/、Codex 的 AGENTS.md、Cursor 的 .cursor/rules/*.mdc）。
  3. 还是不动手，就把这句话直接粘给它：「用 diffcycle_measure 量一下这个页面和设计稿的差异，把 diff 和 withinGate 给我。」
工具报参数不合法 参数

多半在用旧的嵌套写法。现在设计稿来源用扁平参数：

  • designPngPath：本地 PNG 路径
  • designFigmaUrl：Figma 节点链接

两者二选一，outputDir 可以省略（默认 .diffcycle/measurements）。

闸门一直拒绝写入，说找不到测量记录 写闸门
  1. 先跑一次成功的 diffcycle_measure——闸门依赖测量记录，没有记录它只能拒绝。
  2. 确认测量目录和闸门读的是同一个：默认都是 .diffcycle/measurements，不一致就用 DIFFCYCLE_GATE_MEASURE_DIR 指定。
  3. 看 .diffcycle/gate.log，里面有每次拦截的原因。
闸门装了但没生效 写闸门
  1. 宿主侧可能需要审批或信任：Codex 的非托管 Hook 需要 review + trust 才运行。
  2. 确认退出码是 2：只有 2 + stderr 才是阻断，其它退出码通常只警告放行。
  3. 确认 stderr 有内容，没有内容的拒绝等于没拒绝。
  4. 看 .diffcycle/gate.log 里有没有这条记录。没有 → 闸门根本没被调到，去检查宿主的 Hook 配置。
误伤了正常修改 写闸门
  1. 临时关掉：DIFFCYCLE_GATE_DISABLED=1。
  2. 单独跑一次 measure，看是哪些区域超标——summary.json 里按占比排序就能看到元凶。
  3. 确认不是流程问题：如果每次改完都没重新测量，闸门会一直认为「拿旧测量糊弄我」，这是设计如此。
差异几乎全在空白区域 渲染

字体没加载或资源缺失导致重排。用浏览器的网络面板确认两边字体一致；这类差异通常表现为大量 added / removed 区域，而不是 modified。

数字比我预期的严格 口径

看的是严格口径，它不给任何容差。同时看 gate 与 perceptual 两个口径：gate 是验收线用的口径，perceptual 回答「人眼能不能看出来」。

整体错位，怀疑是缩放或 DPR 渲染

确认两边的视口宽度与设备像素比一致。视口不同宽时，所有内容都会错位，差异会铺满整页。

页面看起来是空的 / 只有骨架 渲染
  1. 确认 candidateUrl 指向的是渲染完成后的页面，不是源码目录或开发服务器的占位页。
  2. 确认页面在浏览器里手工打开是正常的。
  3. 确认不是 SPA 还没 hydration 完成——必要时等页面稳定后再测。
Figma 节点拉不下来 鉴权
  1. 确认 FIGMA_TOKEN 存在且对目标文件有读权限。
  2. 确认节点链接是节点链接（带 node-id），不是文件首页。
  3. 只是想先跑通链路的话，先用 designPngPath 走本地 PNG。
安装器报错或找不到 Node 安装
  1. 用 Node 的绝对路径调用："C:/Program Files/nodejs/node.exe" scripts/install-codex.mjs --target .。
  2. 确认版本 ≥ 22：node -v。
  3. 先加 --check 看它到底想改什么，再让它动手。
我想让 Agent 量，但不想被拦 写闸门

只装 MCP 服务，不装写闸门。Agent 会去量，但没有人拦它宣布「已经好了」——这个取舍由你决定。

隐私与数据#

  • 默认全在本机：设计稿与页面都在本地比对，产物写在本地目录。
  • 网络出口只有一处：FIGMA_TOKEN 仅用于从 Figma 拉取设计稿节点；不配这个变量就不会访问 Figma。
  • 不写凭据值：安装器只声明变量名，凭据由宿主环境继承，不进代码库也不进前端。
  • 需要授权的动作：d2c_request_approval 与 d2c_authorize_patch 属于显式授权类动作，不自动放行。
文档页里没有留任何邮箱

联系入口由站点的公开 issue 通道承担。

卸载#

  1. 删掉 MCP 注册

    从宿主配置里移除 [mcp_servers.diffcycle] / mcpServers.diffcycle 段。

  2. 删掉规则与 Skill

    删除安装器写的 .claude/skills/、.claude/agents/、.cursor/rules/*.mdc、仓库根 AGENTS.md 中属于 DiffCycle 的段落，以及 Kiro 的工作区 Agent 与 PreToolUse 写闸门。

  3. 删掉产物目录

    .diffcycle/（含 backup/、measurements/、gate.log）。

  4. 撤销环境变量

    移除 FIGMA_TOKEN、DIFFCYCLE_GATE_* 等。

要回滚某一次改动

安装器改既有配置前会在 .diffcycle/backup/ 留一份备份，直接覆盖回去即可。
